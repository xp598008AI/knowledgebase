# 图文技术文档制作规范

状态：Draft（适用于个人技术知识库）

## 1. 目标

以 Markdown 作为主文档，将原理图、系统架构图、通信时序图、状态机、波形和测试截图嵌入正文。图像文件独立保存，便于 GitHub 网页展示、版本管理和 ChatGPT 检索文字说明。

## 2. 推荐目录

```text
主题目录/
├── TOPIC.md
└── images/
    ├── topic-system-architecture.png
    ├── topic-sequence.svg
    └── topic-test-waveform.png
```

图片应优先放在对应主题目录下的 `images/` 子目录，不建议将所有图片混放在仓库根目录。

## 3. 在 Markdown 中插图

图片与 Markdown 文件位于同一主题目录时，使用相对路径：

```markdown
![图 1：系统架构图](images/topic-system-architecture.png)

**图 1：系统架构图。** 说明图中模块边界、关键接口和数据/能量流向。
```

每张重要图片应包含：
- 图号和准确图名
- 图片表达的结论或阅读重点
- 关键模块、信号、状态或参数解释
- 对应需求、标准、代码版本或测试记录（如适用）
- 图片来源与审核状态

## 4. 图片格式选择

| 类型 | 推荐格式 | 注意事项 |
|---|---|---|
| 架构图、流程图、状态机 | SVG 或 PNG | SVG 适合线条与文字；确保字体和标签清晰 |
| 电路图、波形图、示波器截图 | PNG | 保留坐标、单位、通道标注和测试条件 |
| 扫描页、照片 | PNG/JPEG | 需要补充来源、页码或拍摄条件 |
| 大型原始测试资料 | 原文件或压缩包另行归档 | Markdown 中链接到资料，不要用截图代替原始证据 |

## 5. 文件命名

建议使用小写英文、数字和连字符，避免空格及过长名称，例如：
- `evcc-system-architecture.png`
- `dc-v2h-sequence.svg`
- `mosfet-switching-waveform.png`
- `fmea-fault-chain.png`

## 6. 图文技术内容的可信度

- AI 生成图用于解释概念时，标注“概念示意图”，不可作为规范原文或实测证据。
- 标准时序、引脚定义、协议字段和安全要求必须对照项目适用的正式标准与设计输入复核。
- 测试波形应注明测试对象、软硬件版本、仪器/探头、工况、单位及结论；不可用生成图片冒充实测结果。
- 代码截图不应替代可检索的源代码。
- 导入前确认图片不包含密码、令牌、客户信息、公司机密或未获授权披露的专利内容。

## 7. 插图验收清单

- [ ] 图片已提交到仓库，且路径大小写完全一致
- [ ] GitHub 网页能正常渲染图片
- [ ] 图片在正文中有图号、图名和解释
- [ ] 图片中的文字、单位、箭头与信号方向可读
- [ ] 正式标准结论有可追溯来源
- [ ] 概念图与真实测试证据有明确区分
- [ ] 图片未泄露敏感信息
- [ ] 文件名、目录和索引链接符合约定

## 8. 图片导入流程

1. 将此前生成或用户提供的图片上传到当前对话。
2. 确认图片主题、文件名、来源和是否允许存入此仓库。
3. 将图片文件加入相应的 `images/` 目录。
4. 修改对应 Markdown，使用相对路径嵌图并添加工程解读。
5. 在 GitHub 网页打开文档，检查图像显示与链接。
6. 在 ChatGPT GitHub 连接器中测试是否能检索到图旁的文字说明。

注意：当前知识库的文本文件创建流程不能直接把图片二进制内容当作 Markdown 文本写入；图片本身必须以图像文件形式上传或通过支持二进制内容的流程提交。
