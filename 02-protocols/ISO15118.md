# ISO 15118 与充电通信

状态：Draft（版本与条款待依据正式标准核实）

## 1. 先明确版本边界
ISO 15118 不同部分及版本的消息集合、流程和功能范围并不完全相同。分析协议行为前，先确认适用标准部分与版本（例如 ISO 15118-2 或 ISO 15118-20）、AC/DC/双向能量传输场景、车辆与 EVSE 支持的协议能力、通信安全配置，以及项目采用的测试规范与勘误信息。不要把某个版本的消息、状态或时序直接套用到另一版本。

## 2. 从系统角度理解通信链路
典型逻辑链路可分为连接与导引状态识别、PLC 通信链路建立、会话与协议协商、必要时建立安全通信、服务与充电参数协商、按 AC/DC 模式执行充电流程、停止能量传输并释放连接。此为概念流程；准确消息顺序、必选/可选消息和状态条件必须查阅项目适用的标准版本。

## 3. EVCC/SECC 软件模块建议
| 模块 | 责任 | 典型输入/输出 |
|---|---|---|
| Link Manager | 管理底层链路与链路状态 | 链路建立、丢失、质量 |
| Session Manager | 会话生命周期、超时和清理 | 会话 ID、会话状态 |
| Protocol Negotiation | 协议版本/能力协商 | 支持列表、选定协议 |
| Message Handler | 编解码、字段校验、消息分发 | 消息对象、错误状态 |
| Application State Machine | 业务流程与合法状态转换 | 当前状态、动作、退出条件 |
| Energy Parameter Manager | 目标值与边界仲裁 | 请求值、允许值、测量值 |
| Security Manager | 安全通信相关流程（按配置） | 安全状态、验证结果 |
| Diagnostics & Logging | 统一错误码、时间戳和追踪 | 事件、超时、错误原因 |

模块拆分应考虑现有协议栈和 AUTOSAR 架构，不要求每项必须独立部署。

## 4. 时序与异常分析方法
对每个流程记录消息方向、前置状态与触发条件、关键字段和单位、等待响应时间与超时策略、正常/拒绝/无响应分支、重试规则、会话资源清理方式，以及对功率输出和接触器状态的影响。互操作性问题应保存双方日志、统一时间基准、协议消息跟踪、软件版本、配置和测试环境。

## 5. 安全通信检查项
- 安全通信配置与证书信任策略符合项目要求
- 证书有效期和验证失败的行为有明确需求
- 时间同步及证书有效期检查可靠
- 证书安装、更新或过期后的行为明确
- 安全通信失败、证书验证失败、后端不可用时的处理符合需求
- 日志避免输出不必要的敏感身份信息

具体流程与消息要求须依据适用标准、项目安全方案和设计文件核实。

## 6. 典型测试场景
协议能力不匹配；非法消息、缺失字段或越界参数；关键消息超时或乱序；链路中断后恢复；证书无效或过期；参数动态变化；正常停止与异常退出；重复会话、重启和资源泄漏。

## 7. 标准证据规则
每条规范性结论必须记录标准完整编号、版本/年份、条款号、页码、原文摘录或准确摘要，以及审核状态。未核实的条款号不要填写猜测值。
