# EVCC 与充电系统

状态：Draft（工程知识初稿，需结合项目架构审核）
主题：EVCC、SECC、OBC、DCDC、BMS、充电控制器与充放电系统边界

## 1. 核心认识
EVCC（Electric Vehicle Communication Controller）负责车辆侧充电通信及相关协调；SECC（Supply Equipment Communication Controller）负责供电设备侧通信。实际产品中的功能分配取决于系统架构，不能仅凭控制器名称推断所有功能都位于单一 ECU。

需要区分三个层面：
1. 电气连接与导引：连接器、CP/PP、接触器、锁止、绝缘监测等。
2. 数字通信：PLC、协议栈、会话管理、参数协商、证书及安全通信。
3. 功率控制与安全监督：BMS 允许值、OBC/DCDC 控制、接触器控制、绝缘监测、故障响应和安全状态。

## 2. 典型车辆侧分层
| 层级 | 典型职责 | 关键接口/数据 |
|---|---|---|
| 连接与导引 | 插枪识别、CP/PP 状态、锁止反馈 | CP 电压/PWM、PP 电阻/编码、锁状态 |
| 通信物理层 | PLC 调制解调、耦合与信号质量 | PLC Link、SLAC 相关状态 |
| 协议层 | 会话建立、能力协商、充电参数交换 | 协议消息、超时、错误码 |
| 充电应用层 | 充电模式、目标电压/电流、流程状态 | 请求值、限制值、状态机 |
| 车辆能量管理 | BMS 允许充电/放电边界 | 电压、电流、SOC、温度、故障状态 |
| 功率执行与安全 | OBC/DCDC、接触器、绝缘及联锁 | 使能、反馈、诊断、功率实际值 |

这是概念分层，不是规定的 ECU 切分。项目应明确每项功能的唯一责任方、数据所有权和故障时的控制权。

## 3. 关键接口设计检查项
- 每个信号定义单位、范围、精度、刷新周期、超时值、无效值和初始化行为。
- 区分请求值、允许上限、实际测量值，不能把三者当成同一信号。
- 明确电压/电流限制的仲裁规则，例如协议请求、BMS 限制和功率模块限制冲突时由谁决定最终限值。
- 对关键命令定义有效条件、执行反馈、超时和失败后的安全响应。
- 对跨 ECU 数据定义通信丢失、旧数据、计数器/校验错误及恢复策略。

## 4. 状态机设计建议
状态机应描述连接识别、通信链路建立、会话建立与能力协商、预充/电压匹配（按适用架构）、能量传输、正常停止、故障停止/紧急退出、连接释放与恢复。

每个状态都要明确进入条件、动作、成功条件、超时、异常转移、可否重试及退出后的输出状态。实际状态名称和顺序必须以适用协议版本及项目实现为准。

## 5. 常见失效场景
| 场景 | 可能原因 | 建议诊断证据 |
|---|---|---|
| 插枪后无通信 | CP 状态错误、PLC 耦合/供电问题、SLAC 不匹配 | CP 波形、PLC 日志、链路状态 |
| 会话中断 | 超时、报文错误、链路质量差、对端重启 | 时间戳、错误码、重试计数 |
| 目标值不一致 | 单位/缩放错误、数据过期、限制仲裁不一致 | 请求值、BMS 限制、模块限制及实际值 |
| 停止后仍有输出 | 状态机竞争、命令与反馈不同步、执行器故障 | 使能信号、接触器反馈、电压/电流波形 |
| 故障无法恢复 | 错误锁存、清除条件不完整、状态未复位 | 故障状态、复位条件、恢复时序 |

## 6. 验证清单
- 正常充电流程及中止流程
- CP/PP 状态边界和抖动
- PLC 建链失败、通信超时、报文异常
- BMS 限制值动态变化及边界值
- 关键 ECU 重启、通信丢失和恢复
- 正常停止与异常停止的执行反馈
- 需求—设计—测试用例双向追溯

## 7. 需要项目确认
实际 ECU 分配、协议标准与版本、信号字典、接口周期与超时参数、失效安全状态及安全分析依据。
