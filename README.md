# 个人技术知识库

## 目标
建立可检索、可追溯、可持续维护的汽车电子研发知识库，服务于技术学习、系统设计、故障定位、ASPICE、功能安全、测试验证和专利挖掘。

## 知识范围
- 充电系统：EVCC、SECC、OBC、DCDC、BMS、超充
- 通信协议：ISO 15118、IEC 61851、DIN 70121
- 软件工程：AUTOSAR、BSW、RTE、接口、状态机
- 开发流程：ASPICE、需求追溯、设计评审
- 安全与失效分析：ISO 26262、FMEA、FTA、诊断
- 硬件工程：功率器件、驱动、采样、电源、EMC
- 验证测试：DV/PV、故障注入、测试覆盖率
- 专利与工程经验：创新点、根因分析、设计复盘

## 目录约定
- `00-index/`：主题索引
- `01-charging/`：充电系统
- `02-protocols/`：通信协议与标准
- `03-software/`：软件架构与实现
- `04-process/`：ASPICE 与开发流程
- `05-safety/`：功能安全与失效分析
- `06-hardware/`：硬件与功率电子
- `07-verification/`：验证与测试
- `08-patents/`：专利构思与交底书
- `09-lessons/`：工程经验复盘
- `10-source-register/`：来源、版本、许可与审核记录
- `templates/`：知识卡片、测试报告、失效分析模板
- `attachments/`：经确认允许存储的附件；大文件和敏感文件需单独评估

## 文档管理规则
1. 技术知识优先使用 Markdown；原始 PDF、代码、测试数据可按需保留。
2. 关键结论必须记录来源、版本、章节/页码或代码路径。
3. 明确区分标准要求、原始证据、工程经验、推断和待验证假设。
4. AI 生成内容默认标记为 Draft，人工核实后才能标记 Approved。
5. 不存放密码、访问令牌、私钥、客户个人数据或未经批准的公司机密。
6. 重要更新应记录变更原因和影响范围；过时文档标记 Deprecated，不随意删除历史证据。

## 文档状态
- Draft：草稿
- In Review：待审核
- Approved：已审核
- Deprecated：已废弃

## 推荐工作流
收集资料 → 提取摘要 → 核实来源 → 人工审核 → 提交版本 → 更新索引 → 用真实问题验证检索效果。

## 使用 ChatGPT 检索时
要求回答列出实际读取的文件路径和证据位置。未找到证据时应明确说明，不得把通用知识或推测描述成仓库中的事实。
