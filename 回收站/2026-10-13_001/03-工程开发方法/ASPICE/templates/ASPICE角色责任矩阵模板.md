# ASPICE 项目角色与责任矩阵模板

> 状态：Draft 模板。角色名称可按组织调整；RACI 分配必须由项目批准，不能把本示例视为标准强制组织结构。

## 1. RACI 定义

- **R — Responsible**：执行工作。
- **A — Accountable**：对结果最终负责；每项活动原则上应明确唯一最终负责角色。
- **C — Consulted**：提供输入或专业意见。
- **I — Informed**：接收进展或结果信息。

## 2. 角色清单

| 角色 | 主要职责（项目化定义） | 替补/授权规则 |
|---|---|---|
| 项目经理/项目负责人 | 计划、资源、进度、风险、里程碑与跨团队协调 | 待填写 |
| 系统工程负责人 | 系统需求、系统架构、接口和系统验证协调 | 待填写 |
| 软件负责人 | 软件需求、架构、详细设计、实现和软件验证协调 | 待填写 |
| 测试负责人 | 验证策略、测试设计/执行、结果报告和回归管理 | 待填写 |
| 配置管理员 | 配置项标识、版本、基线、发布和状态记录 | 待填写 |
| 质量保证（QA） | 按计划检查过程遵循和工作产品一致性，记录发现项 | 待填写 |
| 功能安全/网络安全负责人（如适用） | 负责相应分析、要求、独立性和接口协调 | 待填写 |
| 产品/客户接口人 | 澄清利益相关方需求、确认验收和交付约束 | 待填写 |

|---|---|---|---|---|---|---|---|---|
| 过程适用性矩阵与项目计划 | A/R | C | C | C | C | C | C | C |

| 系统需求与系统架构 | I | A/R | C | C | I | C | C | C |
| 软件需求与软件架构 | I | C | A/R | C | I | C | C | I |
| 测试策略、设计与执行 | I | C | C | A/R | I | C | C | I |

| QA 过程检查与发现项跟踪 | I | C | C | C | C | A/R | C | I |
| 变更影响分析与批准 | A | R | R | R | C | C | C | C |

## 4. 使用规则

- 为实际项目补充团队名称、人员、权限和替补人。
- 任何活动若缺少 A 或有多个互相冲突的 A，应在项目启动阶段解决。
- QA 的检查职责应与被检查活动的执行责任合理区分；独立性要求以项目/组织规则为准。
- 安全相关职责、独立验证职责和批准权限需按适用标准及项目计划进一步细化。
- 角色变更应同步更新项目计划、权限配置、评审名单和基线责任信息。
