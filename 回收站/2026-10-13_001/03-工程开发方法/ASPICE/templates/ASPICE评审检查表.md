# ASPICE 工程评审检查表模板

> 状态：Template / 使用前按项目过程、客户要求和采用的 PAM/PRM 版本裁剪。

## 1. 评审基本信息

| 字段 | 内容 |
|---|---|
| Review ID | REV-XXX |
| 评审对象 | 需求/架构/详细设计/代码/测试规范/测试报告/变更 |
| 文档或配置项版本 | 版本号、提交 SHA 或基线 ID |
| 评审日期 | YYYY-MM-DD |
| 参与角色 | 作者、技术评审人、测试、系统、QA 等（按项目适用性） |
| 检查表版本 | 本检查表版本或项目专用版本 |
| 评审结论 | 通过 / 带条件通过 / 退回（按项目规则） |

## 2. 通用检查项

- [ ] 评审对象和版本明确，且与受控基线一致
- [ ] 输入完整，假设、约束、接口和未决事项已列明
- [ ] 内容一致、可理解、可验证，术语和 ID 使用统一规则
- [ ] 与上游需求、架构和相关工作产品建立追溯
- [ ] 异常路径、边界条件、诊断和恢复行为已考虑
- [ ] 变更历史和影响范围清晰
- [ ] 发现项已编号，包含事实、风险、责任人和截止日期
- [ ] 评审结论、批准状态和后续行动可查
- [ ] 发现项关闭后有复核证据

## 3. 需求评审专项

- [ ] 每条需求有唯一 ID、来源和责任方
- [ ] 需求陈述单一、明确、必要且无歧义
- [ ] 输入、输出、触发条件、时序、范围和错误行为清楚
- [ ] 验收准则可测量/可判定，验证方法已定义
- [ ] 与其他需求无冲突或重复
- [ ] 分配到系统/软件/硬件元素，或有未分配理由
- [ ] 派生需求有依据，上下游追溯关系完整

## 4. 架构与接口评审专项

- [ ] 系统/软件元素职责和边界明确
- [ ] 关键接口定义方向、单位、范围、时序、错误处理和所有者
- [ ] 数据流、控制流、状态迁移和依赖关系一致
- [ ] 需求分配完整，关键约束有对应架构决策
- [ ] 超时、复位、掉电、重入、通信丢失等场景按适用性分析
- [ ] 架构风险和替代方案/权衡已记录

## 5. 代码/实现评审专项

- [ ] 实现与批准的需求、设计和接口一致
- [ ] 错误处理、边界值、资源释放、并发/时序问题已检查
- [ ] 编码规范、静态分析规则和告警处置可追踪
- [ ] 代码提交可关联需求、缺陷或变更单
- [ ] 构建和依赖版本可复现

## 6. 测试规范/报告评审专项

- [ ] 用例来源、前置条件、步骤、输入、预期结果明确
- [ ] 正常、边界、异常和恢复路径覆盖充分
- [ ] 测试环境、工具、数据、配置和被测版本已记录
- [ ] 实际结果与判定准则对应，失败项未被静默忽略
- [ ] 需求覆盖和未覆盖项有统计及解释
- [ ] 缺陷与回归测试关联，测试报告可复现
- [ ] 测试结果与发布基线一致

## 7. 发现项记录模板

| Finding ID | 位置/对象版本 | 客观事实与证据 | 风险/严重度 | 责任人 | 截止日期 | 纠正措施 | 复核结果/关闭证据 |
|---|---|---|---|---|---|---|---|
| REV-F-001 | 文件/章节/版本 | 具体发现及证据链接 | 中 | 姓名/角色 | YYYY-MM-DD | 修订并重新评审 | 待关闭 |

## 8. 评审结束条件

- 所有阻塞项已关闭，或有正式批准的偏差处置；
- 评审结论与未关闭项风险一致；
- 更新后的工作产品已提交到受控位置；
- 追溯关系、版本/基线和相关测试已更新；
- 复核人、结论和关闭证据已归档。
