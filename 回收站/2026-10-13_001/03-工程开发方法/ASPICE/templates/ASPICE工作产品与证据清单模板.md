## 2. 项目启动阶段建议检查的证据类别

| 类别 | 建议检查的证据 | 核心问题 |
|---|---|---|
| 范围与计划 | 过程适用性矩阵、项目计划、里程碑、资源安排 | 做什么、谁负责、何时交付？ |
| 需求工程 | 来源需求、系统/软件需求、评审记录、追溯关系 | 需求可理解、可验证且上下游一致吗？ |
| 架构与设计 | 系统/软件架构、接口定义、详细设计、决策记录 | 设计能实现需求且接口约束明确吗？ |
| 实现与验证 | 代码版本、代码评审、单元/集成/系统测试及报告 | 实现和验证对应同一受控版本吗？ |
| 风险与问题 | 风险登记册、缺陷记录、根因分析、纠正措施 | 问题有责任人、优先级、期限和关闭证据吗？ |
| 配置与变更 | 配置项清单、基线、变更请求、发布记录 | 能重建版本并说明每次变化的影响吗？ |
| 质量保证 | QA 计划、检查记录、发现项、复核/升级记录 | 过程检查有证据，问题是否闭环？ |
| 交付与维护 | 发布说明、已知问题、交付包、维护/支持约定 | 交付内容、限制和接收状态清楚吗？ |

## 3. 状态定义（项目可调整）

- **Draft**：初稿，尚未完成正式评审。
- **In Review**：正在评审，发现项可能未关闭。
- **Approved**：已按项目授权完成批准。
- **Baselined**：已纳入受控基线，变更需走正式流程。
- **Superseded**：被新版本替代，保留历史记录和追溯。
- **N/A**：不适用；必须有依据和批准记录，不能用于掩盖缺失。

## 4. 每项证据的最低信息

- 唯一标识、标题、责任人和当前状态。
- 版本、批准日期、存储位置与适用配置基线。
- 来源/输入、输出/下游引用和接口依赖。
- 评审结果、发现项及关闭证据。
- 变更历史、关联 CR/缺陷和影响分析。
- 如使用自动生成内容，记录来源、验证责任人和审核状态。

## 5. 里程碑审查

- [ ] 本里程碑要求的工作产品已识别并有明确负责人。
- [ ] 必需工作产品已评审/批准，或有获批偏差记录。
- [ ] 追溯链接有效，未出现孤立需求或无来源测试。
- [ ] 相关缺陷、风险、变更和未决问题已透明呈现。
- [ ] 工作产品版本与代码、测试结果和交付基线一致。
- [ ] QA 检查结果和未关闭发现项已进入里程碑决策。
