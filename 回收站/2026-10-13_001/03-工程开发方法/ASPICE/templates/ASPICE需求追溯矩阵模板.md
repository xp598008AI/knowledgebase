## 2. 需求属性建议

| 字段 | 说明 |
|---|---|
| Requirement ID | 全局唯一、稳定的需求标识 |
| Title / Statement | 简明标题和单一、可验证的需求陈述 |
| Source | 来源文档、客户、法规/标准条款或决策记录 |
| Rationale | 需求原因，说明价值或约束 |
| Owner / Allocated Element | 责任人及分配的系统/软件/硬件元素 |
| Verification Method | 测试、分析、检查或演示等验证方式 |
| Acceptance Criteria | 可判定的验收准则 |
| Priority / Criticality | 按项目规则定义的优先级或关键性 |
| Status / Version | 状态、版本、基线和变更历史 |
| Parent / Derived From | 上层需求或派生依据 |
| Verified By | 测试用例、分析记录或检查证据 |
| Change Impact | 变更影响分析及重新验证记录 |

## 3. 每次里程碑的自动/人工检查

- [ ] 无来源的需求是否均有解释和批准？
- [ ] 是否存在没有分配对象的系统需求？
- [ ] 是否存在没有设计映射的关键需求？
- [ ] 是否存在没有验证方法/验收准则的需求？
- [ ] 是否存在未关联需求的测试用例？若是，是否属于合理的健壮性/探索性测试并说明理由？
- [ ] 所有“通过”结果是否对应准确的需求、用例、环境和软件/系统基线？
- [ ] 变更后是否更新追溯关系并执行影响分析？
- [ ] 需求状态、测试结果、缺陷状态和发布基线是否一致？

## 4. EVCC 超时处理示例

| 层级 | ID | 关联关系 |
|---|---|---|
| 利益相关方需求 | STK-REQ-010 | 充电通信异常时按定义策略退出或恢复 |
| 系统需求 | SYS-REQ-042 | 指定阶段在配置时限内未收到有效响应时进入异常路径 |
| 软件需求 | SWE-REQ-118 | 状态进入时启动计时器，按定义条件判定超时 |
| 设计 | SWE-DES-031 | 状态迁移、计时器启停/取消、诊断行为 |
| 单元测试 | UT-201… | 正常、边界、无效响应、重复响应、状态重入 |
| 集成测试 | IT-087 | 通信管理、诊断和状态控制接口 |
| 系统测试 | SYS-TST-054 | 目标系统下端到端异常行为 |
| 缺陷/变更 | BUG/CR | 修复版本、影响分析、回归证据 |

**重要：** 追溯矩阵不是为了把所有单元格填满，而是为了证明需求来源、实现分配、验证覆盖、版本一致性和变更影响均可核查。
