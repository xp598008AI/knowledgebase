# 验证与测试索引

状态：Draft

## 1. 测试资料分类
- 测试计划与验证策略
- 需求验证矩阵和测试用例
- DV/PV、集成、回归、故障注入
- 原始日志、波形、测量数据
- 缺陷单、根因分析和复测证据

## 2. 每个测试批次的最小元数据
| 字段 | 要求 |
|---|---|
| 测试批次/用例 ID | 唯一且可追踪 |
| 产品与版本 | ECU、硬件、软件、标定版本 |
| 测试环境 | 台架、供电、负载、温度、网络配置 |
| 测试设备 | 型号、量程、校准状态（适用时） |
| 前置条件 | 初始状态、配置、故障注入条件 |
| 输入与步骤 | 可重复执行的操作顺序 |
| 预期结果 | 可测量、可判定的通过标准 |
| 实际结果 | 数据、波形、日志与时间戳 |
| 结论 | Pass / Fail / Blocked / Not Run |
| 缺陷与整改 | 缺陷编号、根因、修复版本、回归结果 |

## 3. 覆盖维度
正常路径、边界值、非法输入、超时、通信中断、数据过期、启动/停止/重启/恢复、状态转换竞争、故障注入与诊断响应、需求覆盖、接口覆盖及必要的代码覆盖、变更影响与回归范围。

## 4. 结果文件组织建议
建议按产品、版本和测试批次分层组织。每批次包含 README 测试摘要、test-cases.csv 用例清单、results.csv 结果汇总、logs 原始日志、evidence 波形/截图和 defects.md 缺陷追踪。大文件或受限资料不应为了归档完整而直接上传；先确认存储许可、保密要求和仓库体积影响。

## 5. 判定原则
测试通过必须对应事先定义的预期结果与通过标准。若测试被阻塞、环境无效或证据不足，应使用 Blocked/Not Run 等状态，而不是标记 Pass。
