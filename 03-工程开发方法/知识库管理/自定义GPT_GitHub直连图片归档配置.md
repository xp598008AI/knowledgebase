# 技术图片自动插入知识库：优先采用 SVG 文本直写法

## 统一规则

所有后续技术图片生成、归档、文档插入和验证，统一遵循[自定义 GPT 技术图片归档统一规则](自定义GPT技术图片归档统一规则.md)。下文是操作指南；如有冲突，以统一规则中的路径、元数据和验证要求为准。

## 推荐方法：生成 SVG 源码并直接写入 GitHub

已验证可行的路径是：**将技术图绘制成 SVG 矢量图源码（纯文本），通过 GitHub 文件接口直接创建 `.svg` 文件，再更新 Markdown 插入相对路径引用。** 这样绕过了 ChatGPT 临时生成 PNG/JPG 的二进制提取问题，不需要 Cloudflare、服务器、本地下载或图片 Base64 上传。

本仓库中的示例：
- SVG 文件：[ASPICE V 模型](../ASPICE/images/aspice-v-model.svg)
- 已嵌入图片的文档：[ASPICE README](../ASPICE/README.md)

## 操作流程

1. **确定目标 Markdown 文档**：优先使用现有主题文档；目标路径不确定时先确认，不要猜路径。
2. **编写 SVG 源码**：使用标准 `<svg>`、`<defs>`、`<rect>`、`<path>`、`<text>` 等元素绘制技术架构图、流程图、时序图或知识卡片。给出合理的 `width`、`height`、`viewBox`，为复杂图添加标题和说明；中文字体使用常见中文字体栈。
3. **直接创建 SVG 文件**：通过 GitHub 文件接口把 SVG 源码作为 UTF-8 文本写入目标文档同级的 `images/` 目录。文件名使用小写英文/数字/连字符，避免覆盖已有图。
4. **更新 Markdown**：插入相对引用，例如 `![ASPICE V 模型](images/aspice-v-model.svg)`。不要把 SVG 代码内嵌成巨型 Markdown 代码块。
5. **读回验证**：重新读取 SVG 文件和 Markdown，确认文件存在、相对路径正确、文档已引用图片；如可访问 GitHub 页面，再检查实际渲染。
6. **记录状态**：AI 生成的技术图默认标记为 Draft；图中文字、信号方向、单位、标准版本和技术逻辑经过人工核对后再标记为 Reviewed/Approved。

## 与 PNG/JPG 的区别

- **SVG 文本直写**：适用于结构图、流程图、时序图、分层架构、技术知识卡片。源文件是文本，因此可以直接通过 GitHub 文件接口创建，无需传输图片二进制。
- **PNG/JPG 等位图**：若图片来自图像生成工具，必须实际取得原始图片字节或可访问的文件附件，才能可靠上传。不能用图片 URL、预览描述或伪造的 Base64 代替图片文件。
- **混合策略**：后续技术架构/流程/时序图优先 SVG；只有真实照片、复杂渲染、必须保留的位图素材才使用 PNG/JPG 上传路径。

## 归档约定

- 图文件放在对应 Markdown 同级的 `images/` 目录，跨文档复用的图放到技术图片资产库。
- 图片名称应能表达主题，例如 `aspice-v-model.svg`、`evcc-state-machine.svg`。
- 文档引用必须使用相对路径，避免绑定到个人临时链接。
- 每次提交后读回核验文件和 Markdown。未实际检查 GitHub Actions 运行结果时，不得宣称工作流已通过。
- 不覆盖已有文件；若文件已存在，生成新版本文件名并更新引用。
