# 技术图片资产规范

## 1. 目标

统一管理 ChatGPT 生成、人工绘制、代码生成或外部来源的技术图片，确保图片能被知识文档引用、能追溯来源，并尽量保留可编辑源文件。

## 2. 推荐目录结构

```text
11-visual-assets/
├── README.md
├── electrical/
├── power-electronics/
├── embedded-software/
├── charging/
│   ├── evcc/
│   ├── obc/
│   ├── dcdc/
│   ├── bms/
│   └── charging-pile/
├── safety-process/
└── frontier/
    ├── energy-storage/
    ├── aidc/
    └── sst/
```

若图片是某个知识条目的直接组成部分，可放在该条目的 `attachments/` 或 `assets/` 下；跨文档复用或系列图优先放入 `11-visual-assets/`，避免重复存储。

## 3. 每张图应有的记录

配套 Markdown 说明至少包括：
- 图片标题、主题、版本和创建日期
- 适用场景与核心结论
- 图中符号、缩写、单位和关键参数说明
- 来源类型：AI 生成、人工绘制、代码生成或外部来源
- 外部来源 URL、许可/版权说明（如适用）
- 审核状态和需要进一步验证的技术点
- 使用该图的知识文档相对链接

## 4. 图片格式

- `SVG`：优先用于架构图、流程图、状态机和可编辑矢量图。
- `PNG`：适合复杂渲染图、截图和无损技术插图。
- `GIF`：适合展示时序或动作，但需同时提供关键帧或文字说明。
- `drawio/pptx`：有编辑需求时保留源文件。
- 不要仅保存图片而不保存解释、版本和出处。

## 5. Markdown 引用

同一仓库内使用相对路径，例如：

```markdown
![EVCC 与 SECC 的直流 V2H 时序图](../../11-visual-assets/charging/evcc/evcc-dc-v2h-sequence-v1.png)
```

请按实际文档层级调整相对路径。GitHub Markdown 可以渲染仓库内相对图片链接；提交前需确认路径和文件名准确。

## 6. 技术正确性检查清单

- [ ] 信号方向、箭头、状态迁移和时序先后正确
- [ ] 单位、极性、量纲、阈值和缩写正确
- [ ] 标准名称、版本和条款号已核对
- [ ] 图中示意与规范性要求明确区分
- [ ] 图片内文字清晰，无关键标注截断
- [ ] 复杂图提供文字版解释或可访问的源文件
- [ ] 标明 Draft / In Review / Approved
- [ ] 确认版权、保密和数据许可

## 7. 统一归档原则

生成图片后，先将原始图片上传到对应主题目录，再在同主题 Markdown 中添加说明和相对链接，最后更新索引。不得在未确认上传成功前，将图片链接写成已存在的仓库路径。
