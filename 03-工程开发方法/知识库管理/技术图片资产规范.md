# 技术图片资产规范

## 1. 目标

统一管理 ChatGPT 生成、人工绘制、代码生成或外部来源的技术图片，确保图片能被知识文档引用、能追溯来源，并尽量保留可编辑源文件。

## 2. 统一目录规则

本仓库采用两类存储位置，不另建与实际目录不一致的 `11-visual-assets/`：

- **主题专用图片**：放在所属技术文档旁的 `images/` 目录，例如 `03-工程开发方法/ASPICE/images/`。
- **跨主题复用的图片**：放在 [技术图片资产库](../../06-创新、扩展与职业竞争/技术图片资产库/README.md) 管理；需要时由相关文档引用。
- **待自动归档的真实图片文件**：按资产库说明放入 `06-创新、扩展与职业竞争/技术图片资产库/待归档/`，同时提供同名 JSON 元数据，并遵守自动归档脚本约束。
- 不要为了统一目录而搬动已有历史资料；新增图片按上述规则存放。

## 3. 每张图应有的记录

配套 Markdown 说明至少包括：
- 图片标题、主题、版本和创建日期（若已知）
- 适用场景与核心结论
- 图中符号、缩写、单位和关键参数说明
- 来源类型：AI 生成、人工绘制、代码生成或外部来源
- 外部来源 URL、许可/版权说明（如适用）
- 审核状态和需要进一步验证的技术点
- 使用该图的知识文档相对链接

## 4. 图片格式与写入方式

- `SVG`：优先用于架构图、流程图、状态机、时序图和可编辑矢量图。可将 SVG 源码作为 UTF-8 文本，通过 GitHub 文件接口直接写入 `.svg` 文件，再由 Markdown 相对路径引用。
- `PNG/JPG/JPEG/WEBP/GIF`：属于位图，必须使用真实图片文件字节上传；不能把 URL、描述文字或 SVG 源码保存成这些扩展名。
- `GIF`：适合展示时序或动作，但需同时提供关键帧或文字说明。
- `drawio/pptx`：有进一步编辑需求时，保留相应源文件。
- 不要仅保存图片而不保存解释、版本和出处。

## 5. Markdown 引用

优先使用相对于当前 Markdown 文件的仓库内路径。例如，若文档与图片目录结构为：

```text
03-工程开发方法/ASPICE/
├── README.md
└── images/
    └── aspice-v-model.svg
```

则文档中使用：

```markdown
![ASPICE 开发 V 模型示意图](images/aspice-v-model.svg)
```

引用必须与真实文件路径、大小写完全一致。提交后应重新读取 Markdown 和图片文件确认；可用仓库中的 `scripts/check_image_refs.py` 检查本地图片引用。

## 6. 技术正确性检查清单

- [ ] 信号方向、箭头、状态迁移和时序先后正确
- [ ] 单位、极性、量纲、阈值和缩写正确
- [ ] 标准名称、版本和条款号已核对
- [ ] 图中示意与规范性要求明确区分
- [ ] 图片内文字清晰，无关键标注截断
- [ ] 复杂图提供文字版解释或可访问的源文件
- [ ] 标明 Draft / In Review / Approved
- [ ] 确认版权、保密和数据许可

## 7. 统一归档流程

1. 确定目标主题文档和图片的主归属。
2. 流程图、架构图、状态机和时序图优先生成 SVG 源码；位图则保留真实图片字节。
3. 将图片写入目标主题的 `images/` 目录，或按共享资产库规则归档。
4. 在目标 Markdown 插入相对路径，并附上图示用途、来源与审核状态。
5. 重新读取图片文件和 Markdown，确认路径存在、引用正确。
6. 对仓库本地文件运行图片引用和 Markdown 链接检查；GitHub Actions 是否通过，必须以实际运行结果确认。

不得在未确认文件创建成功前，将图片链接写成已存在的仓库路径。
