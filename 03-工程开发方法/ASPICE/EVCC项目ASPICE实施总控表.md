## 5. 里程碑准入/退出检查

### G0 项目启动
- [ ] PAM/PRM 版本、评估范围、客户特定要求和开发模型已确认。
- [ ] 过程适用性及裁剪决定有依据、责任人与批准记录。
- [ ] 项目计划、里程碑、资源、沟通机制和升级路径已建立。
- [ ] RACI、配置管理规则、QA 计划与风险登记册已建立。

### G1-G3 需求与架构
- [ ] 需求来源、唯一 ID、属性、验收准则和评审状态清晰。
- [ ] 上下游追溯关系可双向查询，孤立需求与无来源设计已检查。
- [ ] 架构、接口、数据、时序、错误处理和约束已评审。
- [ ] 安全、网络安全、诊断、法规和客户要求的接口已识别（如适用）。

### G4-G6 实现与软件验证
- [ ] 代码/构建与需求、设计、测试版本可对应。
- [ ] 代码评审、静态检查和单元/集成测试证据按项目要求归档。
- [ ] 正常、边界、异常、并发、恢复和资源约束场景已考虑。
- [ ] 测试失败已关联缺陷；修复后复测及回归范围有依据。

### G7-G8 系统验证与发布
- [ ] 系统需求有明确验证方法、实际结果与报告引用。
- [ ] 测试环境、工具、配置、标定、软件构建和日志可复现。
- [ ] 发布内容与需求、代码、测试、标定及报告基线一致。
- [ ] 已知问题、剩余风险、限制条件和批准的偏差已记录。

### G9 QA 与关闭
- [ ] QA 按批准计划检查过程遵循与工作产品一致性。
- [ ] 发现项有分级、责任人、期限、纠正措施和复核证据。
- [ ] 未关闭事项已升级并由有权限的角色作出决定。
- [ ] 里程碑结论、风险接受、交付状态和证据位置可追溯。

## 7. 变更控制与基线检查

每个 CR 至少应记录：
- 变更来源、原因、优先级、申请人和目标版本。
- 受影响需求、架构/接口、代码、测试、诊断、风险及相关工作产品。
- 兼容性、回归范围、资源/进度影响和安全相关影响（如适用）。
- 评审结论、批准人、实施提交、测试结果、发布版本和关闭证据。
- 更新后的追溯矩阵、工作产品清单和配置基线。

禁止仅修改文档而不分析实现/测试影响；禁止将未批准变更静默并入正式基线。

## 10. 状态定义

- **Not Started**：未启动。
- **Draft**：已建立初稿，尚未完成评审。
- **In Review**：正在评审或有待处理发现项。
- **Approved**：已由授权角色批准。
- **Baselined**：已纳入受控基线，变更需走正式流程。
- **Blocked**：存在阻塞项，必须记录原因、责任人和升级路径。
- **N/A**：不适用；必须记录理由和批准依据。
