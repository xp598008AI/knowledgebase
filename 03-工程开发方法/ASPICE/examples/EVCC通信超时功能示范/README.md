# EVCC 通信超时功能：ASPICE 端到端示范

> 状态：Draft / 工程学习示例。不是项目批准的安全需求，也不是 Automotive SPICE PAM 官方工作产品模板。

## 目标与边界

以 EVCC 与车辆/充电设备之间的一项“通信超时处理”功能为例，演示如何把需求、架构、状态机、测试、缺陷、变更和基线连成可审查的证据链。示例中的时间阈值、状态名和安全行为均为占位假设，必须由系统安全分析、通信规范、客户需求及项目架构确认后才能用于真实项目。

## 示例链路

`STK-REQ-001 → SYS-REQ-010 → SWE-REQ-021 → ARC-001 / SM-001 → UNIT-UT-021 → INT-IT-004 → SYS-ST-008 → TEST-REPORT-008`

任何需求或设计变更，都应分析受影响的实现、测试、接口、风险和已发布基线；不能只修改需求文本。

## 项目使用前必须确认

1. “通信活动”的定义：有效报文、有效状态更新、心跳，还是协议规定的特定消息。
2. 超时计时器启动、重置、暂停与取消条件。
3. 超时阈值、容差、时钟源、调度延迟和计时精度。
4. 超时后的状态、输出控制、恢复条件、重试上限和故障上报策略。
5. 是否涉及功能安全、网络安全、法规或客户特定要求，以及相应的独立验证要求。
6. 目标项目采用的 Automotive SPICE PAM/PRM 版本、过程适用性与工作产品要求。

## 最小完成判据

- 需求有唯一 ID、来源、可验证的验收准则和批准状态。
- 上下游追溯双向可用，所有链接指向正确版本。
- 正常、边界、异常、恢复和重复故障场景均有测试设计。
- 失败测试关联缺陷；修复后有回归证据。
- 变更经过影响分析、评审、验证和配置基线更新。
- QA 能基于受控证据独立检查过程遵循情况。
